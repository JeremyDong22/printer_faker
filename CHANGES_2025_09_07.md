# Order Processing Updates - September 7, 2025

## Overview
Two critical issues were fixed in the order processing system to enable proper table view functionality and handle return dishes.

## 1. Timestamp Parsing Fix (Critical for Table View)

### Problem
Customer orders were failing to save to the `order_orders` table in Supabase with error:
```
invalid input syntax for type timestamp with time zone: "打印时间: 2025-09-06 22:24:38"
```

### Impact
- **ALL customer orders (客单) were failing** to save to database
- No order-to-dish relationships could be established
- Table view feature couldn't work without order records
- Only kitchen slips (制作分单) were working since they don't use timestamps

### Solution
Added `parse_timestamp()` method in `order_processor.py` (line 304-336) that:
- Handles Chinese format: "打印时间: 2025-09-06 22:24:38"
- Converts to ISO format: "2025-09-06T22:24:38Z"
- Preserves already-correct ISO timestamps
- Falls back to current UTC time if parsing fails

### Code Changes
```python
# Line 500 in process_customer_order()
# BEFORE:
'ordered_at': receipt_data.get('timestamp', datetime.utcnow().isoformat()),

# AFTER:
'ordered_at': self.parse_timestamp(receipt_data.get('timestamp')),
```

## 2. Return Dish Functionality (New Feature)

### Problem
Restaurant needs to handle returned dishes (退菜) when customers cancel or exchange items. Previously, these were either ignored or processed as regular dishes.

### Real Return Slip Format
```
退菜单
(分单)
桌号: B区-B3
菜品数量
(退)五指毛桃山茶1/份

退菜原因: 换团购

单号: 140877542509070050
操作人: 刘运（管理员）
时间: 2025-09-07 20:07:45
```

### Solution Implementation

#### 1. Extended Dish Dataclass (line 22-28)
```python
@dataclass
class Dish:
    name: str
    quantity: int
    station_id: Optional[str] = None
    is_return: bool = False  # NEW: Track returned dishes
```

#### 2. Added Detection Methods (lines 175-182)
```python
def is_return_slip(self, text: str) -> bool:
    """Check if this is a return dish slip (退菜单)"""
    return '退菜单' in text or '退菜原因' in text

def extract_return_reason(self, text: str) -> Optional[str]:
    """Extract return reason from receipt"""
    match = re.search(r'退菜原因[:：]\s*([^\n]+)', text)
    return match.group(1).strip() if match else None
```

#### 3. Updated Dish Parsing (lines 270-302)
The `parse_kitchen_slip_dishes()` method now:
- Detects "(退)" prefix on dish names
- Sets `is_return=True` for returned dishes
- Removes prefix to get clean dish name

#### 4. New Return Processing Method (lines 435-529)
`process_return_slip()` handles the complete return workflow:
- Finds original dish in database (by name, table, and status)
- Updates status from 'pending'/'preparing' to 'returned'
- Records return reason for analytics
- Handles no-match cases with negative quantity entries

#### 5. Updated Main Processing Flow (line 417-418)
```python
# Check if this is a return slip
if self.is_return_slip(text):
    return self.process_return_slip(receipt_data, text, table_no)
```

### Database Operations

#### For Matched Returns:
```python
# Find original dish
result = self.supabase.table('order_dishes').select("*").eq(
    'table_no', table_no
).eq('name', dish.name).in_(
    'status', ['pending', 'preparing']
).order('created_at', desc=True).limit(1).execute()

# Update to returned status

    'status': 'returned',
    'updated_at': datetime.utcnow().isoformat()
}).eq('id', dish_record['id']).execute()
```

# Create negative quantity record
self.supabase.table('order_dishes').insert({
